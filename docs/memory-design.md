# 记忆与连续性设计 v1

> **定位**：产品护城河之一——"它记得你上个月在纠结什么"。陪伴是时间的函数：单次对话再好也只是咨询，跨越数月的连续在场才是陪伴。
> **分工**：本文档（记什么、怎么用、边界）由内容引擎侧维护；**存储与运行时实现归应用侧**。实现建议仅供参考，标注【建议】的可自行决定，未标注的是设计约束。
> **配套**：`contracts/engine-api.md`（记忆块的注入点在其 §2）。

## 1. 设计原则

1. **记忆为对话服务，不为数据服务**：只记会改变哲学家下一句话的东西。
2. **摘要优先于原文**：喂回对话的是蒸馏后的记忆摘要，不是聊天记录回放——上下文预算有限，且逐字复述用户旧话会产生被监视感。
3. **明牌记忆**：哲学家可以自然地表明他记得（"上个月你还在纠结要不要二战"），用户可以让他忘（必须真删）。
4. **本地优先**【建议】：桌宠场景数据先落本地（如 SQLite），账号同步后置。
5. **危机数据特殊对待**：单独存储、最小记录、更严格的保留策略。

## 2. 五个存储层

### 2.1 对话历史（raw）

原始会话记录（会话 id、时间、端来源、messages）。用途：网页端"成长记录"的展示、记忆巩固的原料。**永不整段喂回对话**。

### 2.2 困境时间线（timeline）——记忆系统的脊柱

每次交互一条：

```
{ts, source: pet|web, tags: [来自分类器的困境标签], note?: 一句话摘要（可选，巩固任务生成）}
```

用途：弹语按最近标签选卡；记忆摘要里的"最近在纠结什么"；网页端时间线视图；`requires-stable-mood` 类内容的判定依据。

### 2.3 透镜账本（lens ledger）

哲学家给过什么、用户什么反应：

```
{ts, slug, ref: frameworks/control-dichotomy | concepts/med-9.6, reaction: accepted|contested|ignored}
```

用途：①不把同一个透镜灌给同一个人第三次；②"你上次驳过我这笔账"是最高级的连续性时刻；③长期看是各框架实效的评测数据。reaction 判定【建议】由巩固任务离线打标，不在对话请求路径里做。

### 2.4 用户侧写（profile digest）

少量、持久、经巩固的事实条目，**上限 30 条**，每条：

```
{fact: "在准备秋招，二战决定悬而未决", kind: situation|preference|value|boundary|thread,
 evidence: 会话id, last_confirmed: 日期}
```

- `boundary` 类（"不想聊家人"）优先级最高，直接进每次摘要；
- `thread` 类是未了结的话头（"说过想学画画"），是"上个月你提过……后来呢"的原料；
- 淘汰策略：超上限先淘汰 last_confirmed 最旧的非 boundary 条目；巩固任务负责合并重复与更新过期。

### 2.5 安全日志（crisis log，独立存储）

`{ts, 触发类型}`——**只记发生过，不记用户说了什么**。用途：内容过滤（见 §6）与哲学家人格恢复的门控。不进记忆摘要、不进成长记录展示、不用于任何分析。

## 3. 写入路径

- **请求路径上（同步，轻）**：分类器打的标签 → 时间线追加一条。仅此而已，别的都不在请求路径做。
- **巩固任务（异步）**【建议实现】：会话结束后 + 每周一次，用小模型（haiku/sonnet low effort）跑巩固：给时间线补 note、透镜账本打 reaction、更新用户侧写（新增/合并/确认）。周滚动摘要让"上个月"的查询变得便宜。巩固产出全部是结构化条目，**巩固 prompt 里须声明输出将被程序消费、不得编造**。

## 4. 读取路径：记忆摘要（memory digest）

每次深对话开始时，从存储**确定性拼装**（不在请求路径调 LLM）一个记忆块，预算 **≤600 tokens**：

```
# 关于这位用户（记忆摘要，仅哲学家可见）
- 称呼偏好 / boundary 条目（有则必进）
- 近两周困境：标签频次的自然语言化（"高频：同辈比较、反刍"）
- 未了结的话头：thread 条目（≤3 条，带日期）
- 透镜账本节选：最近给过什么、被驳过什么（≤3 条）
- 内容指令：当前生效的过滤（如"mortality 类内容暂停中"）
```

注入位置见 engine-api §2：system-prompt.md 之后追加。**摘要是给哲学家的参考，不是台词稿**——prompt 侧（内容引擎负责）会规定引用记忆的分寸，见 §5。

## 5. 哲学家怎么用记忆（内容侧规范，将写入宪法/人格层）

- **自然提起，不汇报**："上个月你还在纠结二战"✓；"根据我的记录，你在 8 月 3 日说过"✗。
- **旧话头是最好的开场**：桌宠久别重逢、深对话开场，优先用 thread（"上次你说想先把简历改完——改完了吗"）。
- **被驳过的透镜不原样再递**：换角度或直接引用当时的分歧（"你上次不服这笔账，今天我换个算法"）。
- **绝不在哲学家口中提及危机记录**。破角色时也只面向当下，不翻旧账。
- **记忆冲突时以用户当下的话为准**：侧写说他在准备秋招、他今天说已入职——立即以新为准，巩固任务事后更新。

## 6. 危机与内容过滤的联动

- `crisis-signal` 触发后：`mortality` 类弹语与对话中主动引入死亡冥想类框架**暂停 30 天**【建议值，可调】；期满自动恢复，期间用户主动问哲学（如"斯多葛怎么看死亡"）不在禁区——禁的是产品**主动推送**，不是回答。
- 时间线近两周 self 类标签（self-doubt/rumination 等）占比过半：`requires-stable-mood` 类内容暂停推送。
- 判定逻辑在应用侧实现，阈值集中配置。

## 7. 用户主权（不可协商）

- **查看**：网页端提供记忆内容的完整可见入口（成长记录 = 时间线 + 侧写的用户视图）。
- **删除**：支持三档——删单条侧写、清空某段时间、全部遗忘。删除是物理删除，含巩固产物；"让他忘了这件事"在对话内说出也要能触发（应用侧识别 + 确认流程）。
- **导出**【建议】：一键导出 JSON。
- 危机日志的保留独立于用户删除操作【需要用户拍板：是否随"全部遗忘"一并删除——安全考量与主权原则在此冲突，v1 先随删，留待讨论】。

## 8. 分期建议

- **M1（桌宠 MVP 可用）**：时间线 + 弹语过滤联动 + 危机日志。没有它们弹语就是随机的、不安全的。
- **M2（深对话连续性）**：记忆摘要注入 + 用户侧写 + 巩固任务。"记得你上个月"从这里开始成立。
- **M3（完整体验）**：透镜账本 reaction、成长记录 UI、删除/导出面板。
