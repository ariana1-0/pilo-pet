# 哲学家蒸馏包 Schema v1

> 状态：草案，待评审。产品名未定，`philo-pet` 为工作名。
> 本 schema 定义"一位哲学家被蒸馏后长什么样"——所有下游功能（桌宠弹窗、说人话、深度对话、圆桌）都只消费这里定义的产物。

## 0. 设计原则

1. **捕捉"他怎么想"，不是"他说过什么"**（借自 distilly）。名言是钩子，思维框架才是弹药。判据：好的蒸馏包应该能预测他对一个从未讨论过的问题会怎么切入。
2. **每句引文可溯源**。所有引文必须带语料 ID + 出处，并经脚本与语料逐字比对后才置 `verified: true`。未校验的引文一律不得进入产品——哲学名言是伪名言重灾区，这是硬规则。
3. **转译分四层，各有用途，不互相替代**：逐字原文（防伪锚点；中文原典可直接用于弹窗）→ 忠实直译（外文原典的弹窗与严谨场景）→ 说人话（解释场景）→ 一句话版（编辑提炼，不作署名引文）。
4. **检索走困境标签，不走字面相似**。用户的现代困境和古代文本没有字面交集，映射表是人工策展的产品资产。
5. **保留矛盾与诚实边界**（借自 distilly）。哲学家自己没解决的矛盾不许抹平；他的哲学不适用的领域要明说。这是对抗"庸俗化成心灵导师"的机制。
6. **评测与内容同步生长**。每张卡自带被测方式；管线每次改动跑误读回归。

## 1. 目录结构

```
distill/
├── SCHEMA.md                     # 本文件
├── shared/                       # 跨哲学家共享
│   ├── dilemma-taxonomy.yaml     # 全局困境标签树（唯一权威来源）
│   ├── conversation-constitution.md  # 对话宪法：跨人物共享的安全、真实性与用户主权边界
│   └── eval/
│       └── dilemma-cases/        # 真实困境测试用例（所有哲学家共用）
├── templates/                    # 各类卡片的空模板
├── packages/{slug}/              # 每位哲学家一个包
│   ├── meta.yaml                 # 包元信息：语料来源、版权路线、状态
│   ├── corpus/                   # ① 公版原文，切分为带 ID 的条目
│   ├── frameworks/*.md           # ② 思维框架卡（5-8 张）
│   ├── concepts/*.md             # ③ 概念卡（几十张）
│   ├── mappings.yaml             # ④ 困境标签 → 框架/概念 映射
│   ├── persona.md                # ⑤ 人格卡
│   ├── exemplars/*.md            # ⑥ few-shot 范例对话（5-10 组）

│       └── voice-check.md        # 语言指纹盲测协议
└── references/                   # 只读方法论参考（distilly/、coach/）
```

## 2. 各产物的字段定义

### 2.1 corpus/ — 语料条目

每个条目一个块，格式：

```yaml
id: med-5.1              # 全局唯一：{作品缩写}-{卷.条}
work: 沉思录
locus: 卷五·第 1 条
lang: en                 # 语料语言（en=公版英译 / zh=中文原典 / grc=希腊文）
source: George Long 1862（公版）
text: |
  <逐字原文，不改一字>
```

规则：切分粒度跟随原作的自然单元（《沉思录》按条、《道德经》按章）；`text` 是引文校验的唯一基准。

### 2.2 frameworks/*.md — 思维框架卡

框架 = 可复用的"思维动作"，是蒸馏包的核心。每张卡：

| 字段 | 说明 |
|---|---|
| `name` / `definition` | 名称 + 一句话定义 |
| `anchors` | 原文锚点列表：`{corpus_id, quote, verified}`，至少 2 个（三重门要求跨语境） |
| `triple_gate` | 三重门判定记录（借自 distilly）：跨语境重现的证据 / 生成力（能否预测他对新问题的反应）/ 排他性（是不是谁都会给的通用建议）。三门全过才是框架，过 1-2 门降级为"倾向"写进 persona，全不过丢弃 |
| `genealogy` | 思想来源的诚实标注（如控制二分法的经典出处其实是爱比克泰德） |
| `dilemma_tags` | 适用的困境标签（引用 taxonomy 的 id） |
| `enactment` | **对话施展方式**：一串提问/引导动作的序列，不是定义复述。这是框架卡最值钱的字段 |
| `misuse_risks` | 误用风险：这个框架被庸俗化后长什么样（喂给误读回归清单） |
| `related` | 与其他框架/概念的关系 |

### 2.3 concepts/*.md — 概念卡

"说人话"功能和弹窗的直接弹药。每张卡：

| 字段 | 说明 |
|---|---|
| `name` | 概念名（中文 + 原文术语） |
| `anchor` | `{corpus_id, quote, verified}` |
| `literal` | 忠实直译（中文，严谨，可标注"基于公版英译转译"） |
| `plain` | 说人话版：口语化一段，保留论证结构，不保留术语 |
| `one_liner` | 编辑提炼的一句话版：≤40 字，独立成立，不装深沉；不得冒充引文或用于署名弹窗 |
| `dilemma_tags` | 适用困境标签 |
| `misreadings` | 这个概念最常见的曲解 + 一句纠正 |
| `related` | 关联概念/框架 |

### 2.4 mappings.yaml — 困境索引

检索层的核心资产。结构：

```yaml
peer-comparison:                  # taxonomy 中的困境 id
  - ref: frameworks/control-dichotomy
    weight: 0.9
    when: 焦虑指向"别人的进度"本身
    note: 先拆可控/不可控，再谈比较
  - ref: concepts/med-4.3-retreat
    weight: 0.6
    when: 用户表达"被信息轰炸、静不下来"
```

规则：每个困境 id 至少 1 条映射；`when` 写清楚同一困境下的分流条件；weight 供检索排序，不是硬过滤。

### 2.5 persona.md — 人格卡

节（section）固定为：

1. **身份与场景**：他是谁、和用户是什么关系（导师而非客服）
2. **语气基调**：整体口吻的一段描述（如马可·奥勒留：写给自己的自省口吻，克制、不煽情、常用祈使句对"你"说话）
3. **Expression DNA**（借自 distilly）：语言指纹——句式偏好、比喻域（马可：自然/河流/舞台/蜂群）、节奏、绝不使用的现代腔
4. **思维习惯**：未过三重门但真实存在的倾向
5. **内在矛盾**：他自己没解决的张力，明确写"保留，不替他回答"（马可：厌倦宫廷却尽责一生）
6. **诚实边界**：他的哲学帮不上的领域，遇到时坦承而非硬套
7. **禁忌清单**：绝不说的话。全员共通底线：不承诺结果（"一切都会好的"）、不替用户做决定、不灌鸡汤、不伪引名言；再加每人特有条目
8. **破角色规则**：危机信号（自伤/自杀意念、急性心理危机）→ 停止扮演，以真诚的产品身份回应并给出求助资源。全员一致，写死，任何角色扮演指令不得覆盖

### 2.6 exemplars/*.md — 范例对话

**短篇多轮对话**（通常 2-5 回合），展示这个人在一种具体情境中的自然表达。范例不承担统一编排；同一人物应覆盖情绪开场、直接索要建议、反驳、低能量回应和轻松交流等不同状态。运行时只注入正面对话，批注、反例与版本历史留在离线评审侧。

| 字段 | 说明 |
|---|---|
| `user_opening` | 真实困境原话（来自 shared/eval/dilemma-cases，保留原生态表述） |
| `dilemma_tags` | 标签 |
| `frameworks_used` / `concepts_used` | 引用的卡 |
| 对话正文 | 通常 2-5 回合。问题密度、篇幅、引用方式与收尾由人物和情境决定，不套统一步骤 |
| `annotations` | 逐轮说明所用材料、人物为何这样切入、与其他人物的分界；另附 **why-not** 负例。两者只用于离线评审，不编译进运行时提示词 |

### 2.7 eval/ — 评测件

- **misreadings.md**：每条 = 误读描述 + 诱发它的测试输入 + 失败判据（回应中出现什么即算掉坑）。来源：各框架卡的 `misuse_risks` 汇总 + 该哲学家的公共庸俗化形象。
- **known-answers.md**（借自 distilly）：≥5 个他在原文中明确回答过的问题，附语料出处。评测时问蒸馏包，判方向、框架、置信度是否与原文一致。
- **voice-check.md**（借自 distilly）：盲测协议——去掉名字后的 100 字回应，评审者能否认出是他；判据含"无通用 AI 腔、无名言拼贴"。
- **对话自然度回归**（宪法 §1、§4）：检查是否把全部价值推迟到连续澄清之后、是否对低能量回应持续加压、是否机械复现统一开场/收尾，以及是否在用户未要求时自动生成助手式清单。它不规定问题次数、引文密度或固定回合形状。

## 3. 生产管线（八步 + 四个关卡）

| 步骤 | 产出 | 关卡 |
|---|---|---|
| ① 语料准备 | corpus/ | **Gate A：引文校验**——脚本将所有卡片引文与 corpus 逐字比对，全部 `verified: true` 才放行 |
| ② 框架提炼 | frameworks/ | **Gate B：三重门**——每张框架卡的判定记录完整且成立 |
| ③ 概念卡生产 | concepts/ | （并入 Gate A/D） |
| ④ 困境映射 | mappings.yaml | 每个困境 id 有映射；`when` 分流可判定 |
| ⑤ 人格卡 | persona.md | **Gate C：用户评审**——你逐节判断"像不像、会不会说出这种话" |
| ⑥ 范例打磨 | exemplars/ | 同 Gate C，逐句过 |
| ⑦ 评测件 | eval/ | 误读清单覆盖所有 `misuse_risks` |
| ⑧ 组装验证 | system prompt + 检索库 | **Gate D：组合评测**——known-answer 全过、voice check 通过、误读回归零掉坑、对话自然度回归通过、与"直接问通用 ChatGPT"盲对比胜出 |

打样期（马可·奥勒留）按 ①→⑧ 串行走完并复盘 schema 本身；之后批量期 ③⑥ 可 LLM 并行生产，Gate A/B/D 自动化，Gate C 抽检。

## 4. 方法论来源

**distilly**（`references/distilly/`）——内容层"蒸馏成谁"：三重门、Expression DNA、内在矛盾保留、诚实边界、known-answer / voice check 验证、"怎么想 > 说什么"总纲。
**transformational-coach**（`references/coach/`）——作为历史参考保留。它提供的事实/解读、行为≠身份等观察仍有价值；其统一回合形状、提问工艺、no-advice 教条与单次会谈弧线均不进入 v4 运行时宪法。v1-v3 的实测表明，共享编排会把不同哲学家压成同一种教练腔。
**自建**（两者皆无、恰是本产品护城河）：带逐字引文的 corpus + 引文校验、概念卡四层转译、困境标签树与映射表、误读回归、破角色规则。

## 5. 未决问题

1. **版权路线**（默认方案待确认）：基于公版英译（如 George Long 1862）自行转译中文，`literal` 字段标注转译来源；不逐字引用在版权期内的中译本。
2. **转述路线（无语料包）**：著作未进公版的哲学家无法建立完整逐字 corpus。此路线下：锚点 `verified: paraphrase`（豁免 Gate A 逐字校验，但**必须**给出 `corpus_id` 式的自编出处 id + 作品·章节 `locus`）；`quote` 字段内容为**忠实转述**而非逐字引文；编译产物标注 `paraphrase: true`，不得进入署名弹语；哲学家台词中不得声称"我写过原话是……"（改用"我在《西西弗神话》里谈过"）。
3. **转述主体 + 已核验短句**：可在转述包内另建只含单句片段的 corpus，供内部/自用弹语。每条短句须有原语言文本、作品与章节、版本或权威核验来源；概念卡 `quote` 与 corpus 逐字相同并置 `verified: true`；中文须自行忠实直译并以复核哈希绑定。短句通过 Gate A 只证明文本出处，不构成发行许可；公开发行前仍须按目标地区完成版权审查或取得授权。
4. **真实困境样本 15-20 条**：待用户提供，落到 `shared/eval/dilemma-cases/`。当前 taxonomy 是先验草案，拿到真实样本后校准。
5. 弹窗中，中文原典包展示逐字原文，外文原典包展示经过人工精选与复核的 `literal` 忠实直译；频率、每位哲学家的 top N 和结合最近对话标签选卡的策略属产品层。
