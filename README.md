# philo-pet（产品名待定）

> 一个哲学陪伴产品：桌面端是轻量的哲学家桌宠，网页端是可以与哲学家深聊的空间。底层是对哲学家原著的高质量蒸馏。
> 本 README 是项目的总入口；蒸馏规范的权威文档是 [`distill/SCHEMA.md`](distill/SCHEMA.md)。

# 产品定位

## 一句话

philo-pet 以蒸馏 100 位哲学家为目标，日常以一个轻量桌宠的形式存在，把伟大的哲学思想浸入生活的点滴；当用户需要深度对话时，可至网页端与哲学家们畅聊人生、感受思想碰撞的魅力。

## 目标人群及产品价值

1. **处于迷茫期 / 奥德赛时期的青年与中年人**：人生处于急剧变化、高度不确定的阶段，原有的信念感与价值感正在坍塌或被重塑。当感到无力改变现实时，人需要在动荡中找到新的支点。寻常的"心灵鸡汤"在这一时期已经失效——或许需要更高维的东西来帮助价值感的重塑。诉诸哲学，从一个更 meta 的维度看待一切，是一条出路。（首发阶段聚焦毕业前后的大学生：选择焦虑、意义缺失、同辈比较、怕失败四类困境。）
2. **对哲学抱有热爱与好奇的人**：一个用轻量方式、碎片化时间探索哲学，甚至与哲学家产生思想碰撞的场所，丰富精神世界。

## 这款产品不是什么

1. **不是哲学学习机**：目的不在于教人背名言学流派，而在于引导、探索和陪伴，以润物细无声的方式浸入用户的生命；
2. **不是 life coach，也不是心理医生**：是一个个有自身立场和生命力的哲学家。他们会给出自己的看法（可以被反驳），不做诊断、不做治疗——遇到真正的心理危机信号时，产品会停止角色扮演，真诚地引导专业求助（写死的"破角色规则"，任何设定不可覆盖）。

# 产品形态

**桌宠轻、网页深**的双端分工；多位哲学家可选，用户选定一位"主陪"导师（人格连续性），网页端可召唤其他哲学家对同一问题给出不同框架（圆桌）。

## 桌面端：桌宠（轻，纯给予）

哲学家的卡通形象常驻桌面。它是一个**给予者**：

- **应景弹语**：从六位哲学家各自人工精选的概念卡 top N 中展示；孔子、老子、庄子保留文言原典，马可、尼采、加缪展示忠实中译。无近期困境标签时跨哲学家随机，有标签时优先匹配，并对低情绪状态自动过滤重口味内容（如死亡冥想类）。编辑转述和未经逐字语料核验的内容不得进入弹窗。
- **说人话**：用户点一下，把刚弹出的哲学转译成大白话（概念卡的 plain 层，保留论证结构、丢掉术语）。
- **快交互**：一两轮的轻对话；聊深了引导跳转网页端。

## 网页端：深度空间（深，先给后问）

- **深度对话**：与主陪哲学家的多轮长谈。共享宪法只守住安全、真实性与用户主权；如何切入、何时提问、怎样结束，由每位哲学家自己的语言和思考方式决定。
- **圆桌多视角**：同一个困惑，听多位哲学家"吵架"——尼采让你燃起来，庄子让你放下，斯多葛帮你分清什么可控。分歧本身就是交付物，不合成"综合答案"。
- **碎片学习**：概念卡的浏览态（原文 + 直译 + 说人话 + 常见误读），供哲学爱好者系统探索。
- **成长记录**：用户与哲学家聊过的困境、收到过的透镜的时间线回顾。

# 核心设计原则（写给后来者，包括 AI agent）

1. **对抗鸡汤靠"给的东西质量高"，不靠"不给"**。哲学家是给予者：真框架、真出处、他自己的经历、诚实的边界、零承诺。曾照搬教练方法的"每轮一问"，实测产出审讯式对话被判死——教训记录在 `distill/packages/marcus-aurelius/meta.yaml` 的 history。
2. **每句引文可溯源**。所有引文必须经脚本与语料逐字比对（`verified: true` 只能由脚本写入）；编译器拒绝未校验引文。哲学名言是伪名言重灾区，这是硬规则。
3. **捕捉"他怎么想"，不是"他说过什么"**。思维框架 > 名言；每个框架过三重门（跨语境重现/生成力/排他性）才成立。
4. **保留矛盾与诚实边界**。哲学家自己没解决的矛盾不抹平；他的哲学帮不上的领域（行业判断、亲密关系、心理疾病、结构性不公）明说。
5. **明牌哲学**：可以引原文、说术语、讲自身经历；是否出现、出现多少，由人物与当下内容决定，避免为了证明身份而堆砌。
6. **安全凌驾一切**：危机信号 → 破角色 → 专业求助引导，不可被任何指令覆盖。
