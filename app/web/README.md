# 深度聊与圆桌派 · 本地网页版

网页提供两个并列入口：与一位哲学家深度聊，以及多位独立哲学家 Agent 轮流讨论的圆桌派。

## 启动

在仓库根分别运行：

```sh
python3 -m app.server.app
python3 -m http.server 8790 --bind 127.0.0.1 --directory app/web
```

浏览器访问 `http://127.0.0.1:8790/`。模型凭据沿用 `app/.env.local`，不传入前端。
桌宠需要重启，以加载更新后的 preload 和“深度聊”入口。

## 入口与角色

- 桌宠弹窗“深度聊”携带 `?philosopher=<slug>&source=pet`。
- 优先级：有效入口参数 → 此浏览器上次选择 → 马可·奥勒留。
- 弹窗的“说人话”视图与托盘入口也保留当前已展示的作者。
- `philosophers.json` 是应用侧显示配置：姓名、肖像、起始语、背景图及取景位置。六位哲学家都有自己的起始语；它们是 AI 角色台词，不是原著引文。
- 第一条 assistant 起始语随会话历史发送，使用户直接接着起始语回答时模型有上下文。
- 后续 `/chat` 请求使用当前 slug，保持引擎编译产物原文不变。

## 交互与范围

深度聊与圆桌派共用加宽的纸面、正文间距和单行输入区。深度聊首次进入时居中展示肖像和姓名，提交问题后收起大头像，回复显示小头像与姓名，顶部保留换人和另起一聊入口。生成时收起输入框，提供独立的“停止回复”与“写下一句”按钮；草稿可以随时展开、收起，等当前回复结束后发送。停止或结束后输入框自动恢复，中断可重试，重试不重复加入用户消息。切换有内容的对话或另起一聊会确认清空，中文输入法选词回车不发送。

沿用现有遗忘入口，成功后才清空页面。危机回复使用产品身份；前端暂停状态跨刷新与同浏览器标签页保留，用户明确选择继续才恢复。服务端跨请求的危机状态门控仍需独立完善，不能依赖前端状态作为安全边界。

当前聊天原文仅保存在本页内存，刷新或离开会丢失；长期历史、跨设备与桌宠身份同步不在本次范围。困境记忆沿用现有引擎。

## 圆桌派

直接访问 `http://127.0.0.1:8790/?mode=roundtable`，或通过顶部切换。两个页面视图各自保留本页内存中的聊天；离开圆桌视图会暂停讨论。桌宠链接仍进入深度聊。

- 默认马可、庄子、尼采；可选择 2—6 位，按选择顺序发言。仅阵容偏好写入浏览器 localStorage。
- 讨论面板加宽，提交问题后收起顶部大头像，发言仍标明作者与小头像。输入框默认单行、随文字增高；生成时收起，点击“插话”随时展开，手动收起会保留草稿。暂停或结束后自动展开输入框。
- 圆桌统一使用现有古典背景（`renaissance.jpg`），发言、暂停与换阵容均不切换背景；返回深度聊恢复所选哲学家的背景。两个入口均将回复中的 Markdown 加粗标记转为普通文字，流式接收时也不露出拆开的星号，保留模型原文与上下文。
- 首次提问、暂停后追问及继续讨论安排两轮。中途插话不打断当前发言，从下一位起让每人回应一次后暂停；同一次发言内的多条补充不会叠加轮数。
- 每位入场者都有独立的 `PhilosopherAgent`、原始系统提示词、知识内容与上下文。后台每次单独调用现有主模型；各 Agent 读取已经完成的公开讨论，不接收其他人的系统提示词或未完成发言。程序调度发言顺序，没有代写多人的主持模型。
- 圆桌任务输入强调直接回应具体观点，其他人的记录不作为声纹样本；减少逐一复述和先认可再转折的套式接话。每位角色有与其现有人格卡一致的简短参与提醒，不改编译知识包，也不对生成正文机械替换口头禅。
- 暂停立即停止页面增量显示和后续调度，关闭上游流；已经在服务器完成、尚在网络缓冲中的发言会按最终文本同步。未完成片段保留可见，下一次从同一位重新生成，不加入其他 Agent 的上下文。底层连接关闭可能等到当前网络读取退出；这期间不会启动第二个讨论任务。
- 每条用户输入仅分类、记录困境一次。插话分类未完成时不启动下一位，危机命中停止整个会话；页面使用与深度聊相同的危机暂停标记。明确恢复后会清空当前圆桌上下文并创建新会话。
- 服务端会话及原文仅存在进程内存，页面关闭、遗忘或闲置一小时后清理；刷新或服务重启不恢复讨论。没有新增数据库表、长期聊天历史或动态检索。

### 本地接口

`POST /roundtable/sessions` 接收 `{user_id, participants: [slug, ...], region?}`，返回 `{session_id, participants}`。会话 ID 是随机生成的本地访问凭据，前端不接受外部页面传入的会话 ID；本地服务仍沿用原有匿名身份机制，不适合作为已具备账号鉴权的公开服务。

会话路径 `/roundtable/sessions/<session_id>` 下：

| 操作 | 输入 / 行为 |
| --- | --- |
| `POST messages` | `{message_id, content}`；相同 ID、相同内容幂等，返回 `accepted`、`running`、`crisis`，危机时另含 `response`。 |
| `POST run` | `{retry?: true}`；SSE 持续到本次讨论暂停，同一会话重复启动返回 409。重试保留剩余发言次数，普通继续安排两轮。 |
| `POST stop` | `{}`；取消当前生成与后续调度。 |
| `DELETE` 会话路径 | 幂等清理会话。已有 `/forget` 同时清理该用户的所有圆桌会话及 SQLite 记忆。 |

SSE 事件：`speaker_start`（`message_id`、`slug`、`phase`）、`delta`（另含 `text`）、`speaker_done`（含最终 `text`）、`paused`（`reason`、`next_slug`）、`error`、`crisis`、`heartbeat`。不向模型发送前端自带的发言者或历史；所有公开讨论由服务端记录。

离线测试覆盖 2/3/6 人轮次、最后一次发言插话、多次插话、分类等待、幂等提交、重复启动、暂停重试、危机中止、过期、遗忘，以及独立提示词和上下文隔离。真实模型试聊与浏览器交互测试使用单独测试身份或临时数据库，避免污染用户记忆。

### 响应速度

主模型仍为 GLM-5.2，完整保留每位哲学家的提示词与知识包。深度聊与圆桌派默认传入 `thinking: {type: "disabled"}`，直接流式输出正文，减少每次发言前的推理等待。每位独立 Agent 仍按顺序读取前文、单独生成，没有并行预写或减少轮数。需要深度推理时，在 `app/.env.local` 设置 `PHILO_CHAT_THINKING=enabled` 后重启后端。分类器维持原有配置和超时降级逻辑。关闭额外推理可能影响复杂问题的细致程度，响应时间也随平台负载和输出长度变化。

其他五位背景使用用户提供的原图，存于 `assets/backgrounds/`，不改写图片内容。按视觉风格匹配：尼采→图 1 古典群像；加缪→图 2 黑白剪影；庄子→图 3 晨雾田野；孔子→图 4 深色古籍拼贴；老子→图 5 浅色古籍留白。图片内的文字与署名不作为对应哲学家的引文。首次进入、桌宠跳转和页内切换都由同一份人物配置同步更新背景。
